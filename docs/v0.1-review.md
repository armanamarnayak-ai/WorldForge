# WorldForge v0.1 release candidate

This release proves the complete local workflow: import an OpenAPI document, inspect a typed
world, generate seeded tasks, execute an agent in a stateful simulator, evaluate the result,
persist ordered events, and replay the recorded actions. It requires no paid model API.

## Implemented

- Python package and CLI, versioned Pydantic contracts, exported JSON schemas, and locked
  development dependencies.
- Bounded offline OpenAPI 3 compiler with declared/inferred provenance and compatibility
  reports. The payments example has three resources and eight supported operations.
- Transactional customer/payment/refund state, schema and relationship checks, refund
  conservation, stable IDs, idempotency, and deterministic pre-effect/lost-response failures.
- Seeded duplicate-charge scenarios, an async agent protocol, deterministic reference policy,
  bounded callback waits, step budgets, and lifecycle cleanup including cancellation.
- Evaluation based on resulting state and audit history; exact call/retry/step counters,
  measured elapsed time, and unavailable token/cost measurements.
- Ordered observation/action/result/state events, atomic local JSON run storage, and replay
  that checks deterministic trajectory consistency without calling the original agent.
- Apache-2.0 license, contributor/security policies, architecture/subset documentation,
  issue/PR templates, and GitHub Actions for Python 3.11–3.13.

## Architecture decisions

The core is a modular monolith with independent per-run state. Provider behavior belongs in
adapters. OpenAPI describes interfaces; explicit annotations declare the payments semantics.
JSON run artifacts embed the world and scenario so replay needs neither mutable current-world
files nor agent code. Logical event timestamps are separate from actual run metadata.
See [ARCHITECTURE.md](../ARCHITECTURE.md) and [the compiler subset](openapi-subset.md).

## Manual review

From a checkout on a supported POSIX platform:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
pytest
ruff check .
ruff format --check .
mypy src/worldforge
python -m build

worldforge import examples/payments/openapi.yaml --workspace .worldforge/review
worldforge world inspect --workspace .worldforge/review
worldforge scenario generate --count 5 --seed 42 --response-lost --workspace .worldforge/review
worldforge run --workspace .worldforge/review
```

Replay an actual `WF-...` ID printed by the run, with the same `--workspace`. Inspect its JSON
artifact under `.worldforge/review/runs/`: a successful lost-response run uses three calls,
one retry, and exactly one refund. Reusing existing world/scenario artifacts requires `--force`.

## Known limitations and security boundary

- The compiler implements a documented subset, not arbitrary OpenAPI business semantics or
  complete HTTP behavior. Scenario generation/evaluation and the reference policy target
  the sample payments shape. Auth, transport, pagination, and production fidelity are absent.
- Simulation and compilation do not invoke production APIs. Custom adapters are trusted
  Python code with process permissions; cooperative timeouts do not isolate hostile or
  blocking code. Use external isolation for untrusted agents.
- Runs can contain sensitive observations. There is no automatic secret/PII scrubbing,
  telemetry upload, artifact signing, or external-provider token/cost measurement. Replay
  establishes internal deterministic consistency, not cryptographic authenticity.
- Storage currently uses local files and POSIX atomic-file primitives. Windows is unsupported.
  No dashboard, MCP integration, Failure Oracle, Reality Distillation, EVOLVE, or model-provider
  integration is implemented.

The source is ready for independent review. The next recommended milestone, after v0.1 review,
is v0.2 adapter integration and richer deterministic failure scenarios. No v0.2 work is included.
