# v0.2 contracts, architecture, and compatibility

The development implementation extends the released v0.1.0 modules rather than replacing the
World IR, OpenAPI compiler, payments semantics, async `AgentAdapter`, evaluator, or replay model.
Package version `0.2.0.dev0` identifies an unreleased development build; schema versions identify
artifact contracts independently from package releases.

| Artifact | Released/read compatibility | New development contract |
| --- | --- | --- |
| World IR | Existing `1.0` OpenAPI worlds remain readable. | OpenAPI/static MCP use the same IR; composition uses `1.1` for namespace semantics. |
| Scenario | `1.0` retains legacy fault shape and serialization. | `1.1` permits `FailureSpec`, virtual latency/runtime budgets, and composed scenario binding. |
| Run | Historical `1.0` artifacts retain wire format and original evaluation/replay policy. | New runs use `1.1` with resource report, additional events, and optional certificate linkage. |
| Event envelope | `1.0` typed context/sequence/payload remains supported. | New named event payloads are verified by the `1.1` run replay grammar. |
| Search / certificate / resource report | No v0.1 contract existed. | Independent `1.0` contracts. |

`schemas/world-1.0.json`, `scenario-1.0.json`, and `run-1.0.json` are frozen released contracts.
The schema exporter writes separate `*-1.1.json` files for current readers plus the new
`search-1.0.json`, `failure-certificate-1.0.json`, and `resource-report-1.0.json` files. Current
reader schemas accept their supported versions; a file's filename is the reader generation,
not an instruction to relabel every old embedded world/scenario as `1.1`.

No bulk migration is required to read/replay old artifacts. A v0.1 reader does not understand
new `1.1` artifacts; use the new package for those. To author richer failures or nondefault new
budgets, set scenario schema `1.1` deliberately. Do not edit an old run to claim a new schema or
recompute a historical evaluation in place. Replay fixtures recorded from the immutable v0.1.0
source cover both a safe run and a historically successful run whose changed-key retry would
now be classified as unsafe. New runtime runs use the stronger explicit policy.

## Module boundaries

- `models.py`: bounded contracts for shared IR/state/scenarios/actions/events/runs and new
  failure, search, certificate, provider, composition-facing, and resource information.
- `compiler.py` / `mcp.py`: bounded local declaration compilation into the same IR, with
  declared versus inferred provenance and transparent unsupported constructs.
- `simulation.py`: validated deterministic state transitions, namespaced refund bindings,
  occurrence-selected failures, initial-snapshot reads, duplicate delivery, and virtual clock.
- `composition.py`: explicit service ownership, qualified IDs, schema references, declared
  cross-service links, and scenario binding.
- `agents.py` / `providers.py`: existing async agent lifecycle, safe/vulnerable local policies,
  and vendor-neutral `ProviderRequest`/`ProviderResponse` contracts and usage records using a
  deterministic CI provider.
- `runtime.py`: callbacks/budgets, ordered observable events, ledger evaluation, unsafe retry
  detection, resource attachment, and version-aware strict recorded-action replay.
- `resources.py`: provenance-bearing available measurements, diagnostics, and bounded summaries.
- `oracle.py` / `certificates.py`: finite deterministic search order, deletion minimization,
  repeated verification, self-contained evidence validation, and local persistence.
- `storage.py` / `cli.py`: real artifact storage and workflows without a production execution layer.

## Observable evidence and determinism

Runs retain their world/version, scenario seed/parameters/initial state, selected faults,
agent metadata, actions/results, state transitions, evaluation, and resource records.
`FAILURE_INJECTED`, `SIMULATED_LATENCY`, `PROVIDER_USAGE`, `RESOURCE_USAGE`, and `RESOURCE_WARNING`
extend observable run events. Search events separately cover start/completion, candidate tests,
discovery, minimization, verification, and certificate creation. These are available decisions
and effects, never hidden chain-of-thought.

The simulator is deterministic for fixed inputs and recorded actions. Search candidate order
is deterministic; real-time budget exhaustion, external agents, artifact IDs, and creation times
can vary. Virtual latency is a deterministic simulation measurement; wall-clock latency is
observed runtime metadata. Replay verifies the trajectory and deterministic resource values
without remeasuring elapsed time or rerunning the agent/provider. Reproduction deliberately
runs a fresh explicitly selected agent and reports observed criterion matches.

The Failure Oracle currently owns the payments search family rather than a generalized optimizer.
Composition establishes namespaces and declared state relationships rather than inventing service
business policies. The provider boundary reports what an adapter supplies rather than assuming
tokens, costs, rate limits, or external inference determinism. Each boundary permits further
reviewed extension without implementing future telemetry, fidelity, learning, or cloud systems.
