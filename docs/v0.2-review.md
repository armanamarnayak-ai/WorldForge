## Scope

Implemented modules extend the existing World IR/compiler/simulator/runtime/CLI with static MCP
compilation, typed deterministic failures, resource provenance/reporting, provider-neutral mock
adapters, service namespaces/declared links, bounded Failure Oracle search and deletion
minimization, repeated verification, and structured inspectable/reproducible certificates.
The adversarial refund example detects an unsafe changed-key retry; refund conservation and
idempotency remain enforced and no actual double refund is claimed.

## Compatibility

Released world/scenario/run `1.0` JSON schemas remain frozen. New reader schemas support existing
artifacts; richer scenarios/composed worlds/new runs deliberately use `1.1`. Certificates, search
specs, and resource reports are independent `1.0` contracts. Original v0.1 recordings preserve
their original wire/evaluation/replay policy. See [architecture notes](v0.2-architecture.md).

## Manual review commands

Run the README basic OpenAPI workflow in a fresh workspace; inspect and replay real run IDs.
Run the MCP payments workflow, then the composed payments/email example. Run the Failure Oracle
with `examples/oracle/refund-search.json` and `vulnerable-reference`, inspect its actual certificate,
reproduce it, replay associated runs, and compare with `reference`. Inspect real resource reports
and aggregates; verify missing tokens/cost are reported as unavailable. Repeat the basic and
Oracle workflow using the built wheel from outside the checkout.

The [Oracle](v0.2-failure-oracle.md), [MCP](mcp-subset.md), [composition](v0.2-composition.md),
and [resource/provider](v0.2-resources-providers.md) guides contain executable commands and explain
expected nonzero exits for no qualifying search failure or safe-agent reproduction comparison.

## Security and limitations

Inputs/search/runtime/artifact work is bounded, schemas remain offline, and built-in workflows
execute synthetic effects only. Custom Python agents/providers are trusted code and not sandboxed;
blocking code requires external controls. Artifacts may contain sensitive observations; automatic
scrubbing is absent. Certificates are local validated evidence, not cryptographic attestations.

The Oracle supports the payments family, finite configured conditions/seeds, and deletion
one-minimality when checks complete; it is not globally optimal or a general agent-safety proof.
Verification ratios are empirical, severity is documented heuristic, and external inference can
vary. MCP input is static, email is deliberately small, and virtual latency is not production
performance. No real-provider SDK or live MCP integration is required or shipped.

Dashboard work is deferred. Reality Distillation, telemetry/log/HAR ingestion, fidelity calibration,
Capability Genome, EVOLVE, adaptive curricula, training/RL, autonomous self-modification,
production API execution, and cloud SaaS are explicitly outside v0.2 implementation scope.
No merge, release, new tag, or package-registry publication is part of this review task.
