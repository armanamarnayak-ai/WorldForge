# Resource Observatory and provider boundary — v0.2 development

New runs embed `resource_report`, an independently versioned `1.0` contract. The report contains
named measurements, warnings, and typed adapter-reported provider records. Each measurement
stores a value or unavailable marker, provenance, source, and unit:

| Provenance | Meaning |
| --- | --- |
| `EXACT` | Direct runtime/simulator counter or measured clock value. |
| `CALCULATED` | Derived from observable counters or explicitly reported usage. |
| `ESTIMATED` | A documented estimate using explicitly configured assumptions. |
| `UNAVAILABLE` | The necessary information was not supplied; `value` is null. |

`EXACT` does not mean independent verification of an external service. Provider numbers remain
typed adapter reports. A local mock's explicitly configured token fixture is a fixture report,
not tokenization or real model consumption.

## Per-run measurements

- `tool_calls`: recorded agent tool invocations.
- `successful_calls`: tool calls minus calls with status at least `400`.
- `failed_calls`: responses with status at least `400`.
- `retries`: consecutive calls to the same tool/arguments after a failure, ignoring changes to
  `idempotency_key` so an unsafe retry is still counted.
- `duplicate_calls`: repeated identical tool/argument pairs, including identical retry keys.
- `world_steps`: logical simulator step delta; a denied action outside the simulator can make
  tool-call count differ from world-step count.
- `simulated_latency_ms`: bounded virtual-clock increments; it is not network latency or a sleep.
- `actual_runtime_latency_ms`: measured monotonic elapsed runtime, including agent callbacks.
- `provider_requests`, `input_tokens`, `output_tokens`, and `total_tokens`: sums of complete
  adapter-reported records. An absent or incomplete field keeps the corresponding total unavailable.
- `estimated_cost_usd`: reported input/output tokens multiplied by explicitly configured
  per-million-token USD prices. Missing tokens or pricing keeps cost unavailable.

Status-based successful calls do not imply that a response was semantically usable; for example,
an injected malformed response retains a successful status while its payload is corrupted.
An internal duplicate delivery is a recorded simulator effect, not another agent tool invocation.
The preserved legacy `evaluation.usage` contract keeps its original counter semantics; use the
new provenance-bearing report for v0.2 summaries, especially changed-key retries.

Warnings use transparent thresholds: `retry_loop` at three failed-operation retries;
`excessive_repeated_calls` when at least half of four or more calls repeat identical arguments;
`high_step_usage` at 100 simulator steps; and `nearing_step_budget` at 80% of the configured
tool-step budget. These are diagnostics, not learned anomaly scores or provider quota predictions.
An explicitly reported quota with at most 20% remaining produces
`nearing_reported_provider_quota`; this reflects the adapter's snapshot, not independent provider
verification. No quota warning is invented when quota metadata is absent.

```bash
worldforge resources report WF-0123456789abcdef0123456789abcdef
worldforge resources aggregate
```

Replace the sample run ID with an actual persisted run. Aggregation sums compatible units across
the workspace's saved run reports, retains an estimated label if any contributing available metric is
estimated, and preserves missing information as unavailable. Warnings are deduplicated. Aggregate
reports contain metrics/warnings rather than copying all raw provider records; per-run reports
retain provider identity and rate-limit metadata. Quota snapshots are not summed into a fabricated
global quota. The CLI bounds the number of loaded runs, up to 1,000, with an
explicit `--limit`; exceeding it rejects the operation rather than silently dropping runs.
A legacy run lacking a v0.2 report cannot silently contribute invented values.

## Provider-neutral adapter foundation

`worldforge.providers.ModelProvider` defines an identity and async reset/complete/shutdown
lifecycle. `complete(request: ProviderRequest)` returns `ProviderResponse`: the request contains
the visible observation and bounded request metadata; the response contains an observable decision
and typed `ProviderRecord`. `ProviderAgentAdapter` supplies a request sequence, validates that
the response identity matches its configured provider, and connects decisions to the existing
`AgentAdapter` runtime. Typed identities carry provider, model, and mock/custom kind. Records carry
request count, optional token counts, optional explicit pricing, and optional exposed rate-limit
limit/remaining/reset metadata. Missing values remain absent; no credentials are discovered and
no hard-coded vendor is required.

`MockProvider` uses the deterministic reference policy. It reports one actual local provider
request for each complete call; tokens are unavailable by default. Optional mock token and
rate-limit fixtures are explicitly configured by a caller, not guessed. The CLI reference path
needs no key:

```bash
worldforge run --agent mock-provider
```

The library can supply prices deliberately:

```python
from worldforge.models import PricingConfig
from worldforge.providers import MockProvider, ProviderAgentAdapter

# Synthetic fixture usage and illustrative configured prices, not a real provider bill.
agent = ProviderAgentAdapter(
    MockProvider(input_tokens=12, output_tokens=4),
    pricing=PricingConfig(input_usd_per_million=1.0, output_usd_per_million=2.0),
)
```

Provider implementations are trusted Python and must return only observable decisions/metadata.
The runtime bounds agent metadata at 64 KiB, decisions at 256 KiB, each provider record at 16 KiB,
the per-run provider record count at 2,000, and accumulated provider receipts at 1 MiB.
If an adapter fails or its receipts cannot be admitted, overall provider totals remain unavailable
instead of presenting an incomplete sum as the complete run. Previously retained receipts remain
inspectable. The runtime does not request hidden reasoning or store arbitrary
credential headers/raw provider responses. A custom adapter can still put secrets in an
observation or metadata: validation is not automatic redaction. No real-provider integration
ships in this development scope; future optional integrations must remain optional and external
model inference must not be described as deterministic replay.
