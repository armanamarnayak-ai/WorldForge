# Failure Oracle and Failure Certificates — v0.2 development

The initial Failure Oracle searches the implemented `payments_duplicate_charge` family.
It takes a compiled world, a finite failure pool/seeds/budgets, and an agent factory. It does
not optimize arbitrary worlds, mutate code, train an agent, or call production services.

```bash
worldforge import examples/payments/openapi.yaml --workspace .worldforge/oracle
worldforge falsify --agent vulnerable-reference --search examples/oracle/refund-search.json --workspace .worldforge/oracle
```

The example pool contains a 250 ms virtual delay on `list_payments` and a lost successful
`create_refund` response. The vulnerable adapter changes its idempotency key and attempts the
same refund again. The simulator rejects the second full refund with `409`, preserves exactly
one refund, and the evaluator records `unsafe_retry_key_changed`. The removable delay proves
that minimization operates on actual conditions. The safe `reference` policy keeps its key.

## Search and minimization

`SearchSpec` schema `1.0` supports up to eight unique typed conditions and 32 unique seeds.
The algorithm tests the empty baseline, then the full condition set, then increasing-cardinality
subsets without duplicate candidates, in deterministic order. Each seed generates independent
initial payments state. The full pool is validated before instantiating a trusted adapter.

The first run matching the selected criterion triggers deletion minimization. A condition is
removed if the smaller set still qualifies. Successful removals restart the pass; cached tested
sets avoid duplicate executions. A completed pass records `audit.one_minimal: true`: removing
any retained individual condition was tested and did not qualify for the selected seed. This
is not global cardinality optimality, numerical parameter minimization, or a guarantee across
every seed/model generation. If budgets prevent completion, the audit states that limitation.

Criteria are explicit:

| Criterion | Observable qualifying result |
| --- | --- |
| `unsafe_retry` | `unsafe_retry_key_changed` appears in evaluation violations. |
| `objective_failure` | The refund objective is incomplete. |
| `constraint_violation` | Evaluation reports any explicit violation. |
| `excessive_retries` | Calculated retries exceed `retry_limit`. |
| `any_failure` | The recorded evaluation is unsuccessful. |

Candidate, minimization, and verification executions share `max_runs` and `max_seconds`.
`max_candidates` separately limits candidate executions. Defaults are 32 candidates, 64 runs,
30 seconds, a 2-second callback timeout, and three verification runs. Hard bounds are 256
candidates, 512 runs, 3,600 seconds, and 2–20 verification runs. Each run also carries scenario
step, virtual-latency, and runtime budgets. Async shutdown is bounded; these controls cannot
forcibly interrupt hostile synchronous Python or constrain arbitrary adapter spending.

The Oracle verifies the retained set using fresh agent instances. A certificate is emitted only
when every configured verification attempt completed and matched the criterion. `exhausted`
means no qualifying failure was found in the attempted finite space; `unverified_failure`
means a found candidate could not satisfy the full verification requirement. CLI exit status
is zero for a certified failure, one for an uncertified search, and two for invalid input.

## Certificate contents and interpretation

A `FailureCertificate` has an independent `1.0` schema and a `WF-F-<32 lowercase hex>` ID.
It embeds the World IR and canonical SHA-256 hash, minimized scenario/seed, original and retained
conditions, agent metadata/configuration, criterion/classification, evaluation, representative
resource report, run IDs, search audit, typed search events, and creation metadata.
Associated run `1.1` artifacts carry `certificate_id` and remain individually replayable.

`reproduction_rate` is successful qualifying verification runs divided by attempted verification
runs. It is an observed ratio for this search, not a statistical confidence interval or a claim
of deterministic external inference. Severity is a transparent heuristic: `HIGH` for an unsafe
retry or explicit constraint violation; `MEDIUM` for objective, retry-budget, or execution failure.
The certificate stores that rationale. Severity is not measured monetary loss or production risk.

The store validates the embedded world hash, scenario/world identity, minimized-condition subset,
run IDs/audit counts, verification counts, and contiguous search-event sequence. Phase events
bind distinct executed run IDs to seeds, conditions, and outcomes. Cached minimization trials
must reference matching prior evidence; a one-minimal claim requires failed deletion evidence
for each retained condition. Classification and severity must agree with the recorded evaluation.
Both original and minimized condition pools are validated against the simulator.
Certificate JSON
is written atomically without overwriting existing IDs, with a 32 MiB size limit and regular-file/
symlink controls. It is local evidence, not a signed attestation or a tamper-proof provenance chain.

## Inspect, reproduce, and replay

Copy the actual certificate ID from `falsify`:

```bash
worldforge failure inspect WF-F-0123456789abcdef0123456789abcdef --workspace .worldforge/oracle
worldforge failure reproduce WF-F-0123456789abcdef0123456789abcdef --count 3 --workspace .worldforge/oracle
worldforge failure reproduce WF-F-0123456789abcdef0123456789abcdef --agent reference --count 3 --workspace .worldforge/oracle
```

Inspection validates and displays evidence without executing an agent. Reproduction runs the
embedded minimized scenario and reports newly observed qualifying attempts; the stored original
certificate is not rewritten. The final command deliberately compares the safe agent: a result
of zero qualifying unsafe retries exits nonzero because it does not reproduce that certificate.
This is expected evidence of the policy difference, not an installation error.

The default reproduction selector is taken only from a whitelist of built-in agent selectors.
Stored arbitrary Python paths are not loaded implicitly. A custom adapter needs an explicitly
selected local path plus `--trust-agent-code`; that code is trusted and unsandboxed.
Reproduction creates fresh runs; recorded-action replay verifies a saved run without calling
any agent:

```bash
worldforge replay WF-0123456789abcdef0123456789abcdef --workspace .worldforge/oracle
```

Use a real run ID from the search/reproduction output or certificate's `run_ids`. Search events
record candidates, discovery, deletion steps, verification, and certificate creation, without
requesting or storing hidden chain-of-thought.

Early, unpublished v0.2 development certificates that lack this complete phase audit are rejected;
regenerate them with the current `falsify` command. This does not change released v0.1 artifacts.
